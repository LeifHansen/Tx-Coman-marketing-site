# Beverage Co-Packing Texas — marketing site

B2B lead-generation site for **https://beveragecopackingtx.com**: an independent introduction service connecting hemp-derived THC, CBD and functional beverage brands (cans, glass, PET, 750 mL) and gummy brands with Texas manufacturing partners.

Static HTML, no framework, no runtime dependencies. Pages are generated by a small Node script and the output is committed, so Netlify serves the repo root as-is (no build step on deploy).

## Structure

| Path | Purpose |
|---|---|
| `src/site.mjs` | Brand, contact details, service + resource catalog, form option lists |
| `src/layout.mjs` | `<head>`/meta/JSON-LD, header with dropdowns, mobile drawer, inquiry form, FAQ, footer |
| `src/art.mjs` | Inline SVG illustrations (hero lineup, format art, service art) built on the brand's can/bottle motifs |
| `src/pages/home.mjs` | Homepage sections + homepage FAQ |
| `src/pages/services.mjs` | Copy for the 7 service pages (titles, descriptions, H1s and body copy carried over from the original SEO pages) |
| `src/pages/resources.mjs` | The 3 guides + `/resources/` hub |
| `scripts/build.mjs` | Writes every `.html` page and `sitemap.xml` at the repo root |
| `scripts/check.mjs` | Post-build checks: links, anchors, ARIA references, one H1, title/description/canonical, JSON-LD |
| `scripts/images.py` | Turns one hero photograph into responsive WebP/JPEG sizes (Pillow) |
| `assets/style.css`, `assets/site.js` | Design system and behavior (nav, drawer, form, analytics) |
| `assets/config.js` | **Lead configuration**: form endpoint/key, GA4 ID, optional webhook |
| `assets/*.svg`, `assets/og-image.png` | Brand mark, logo lockup, favicon, social artwork |
| `marketing/` | Brand guide and SEO roadmap (blocked from the public site in `netlify.toml`) |

Generated pages (don't hand-edit; edit `src/` and rebuild): `index.html`, the 7 service pages, `resources/*.html`, `thank-you.html`, `404.html`, `sitemap.xml`. `hemp-capsule-co-packing.html` is a hand-written legacy redirect.

## Editing workflow

```bash
node scripts/build.mjs     # regenerate pages + sitemap
node scripts/check.mjs     # verify links, metadata and structured data
python3 -m http.server 8080  # preview at http://localhost:8080
```

Commit the regenerated HTML along with your `src/` changes. CSS/JS URLs carry a content hash (`?v=…`), so rebuild after editing `assets/style.css`, `assets/site.js` or `assets/config.js`.

## Hero photograph

The homepage hero is designed around a wide product photograph (cream left side for the headline, products on the right). Until a photo is added it uses the illustrated lineup. To switch to the photo:

```bash
python3 scripts/images.py path/to/hero-photo.png   # writes assets/hero/*
node scripts/build.mjs
```

Use a 16:9 image at least 1600 px wide with the products in the right ~60%.

## Lead form

- Two steps (product → contact) with inline, accessible validation, a loading state and a success state that shows a summary of the brief.
- **Success is shown only when Web3Forms returns HTTP 2xx with JSON `success: true`.** Any other response (error status, `success: false`, empty/non-JSON body, network failure, 20 s timeout) shows a "Not sent" message, keeps the answers, and offers a pre-filled email fallback.
- Spam protection: Web3Forms `botcheck` honeypot + a minimum fill time. Also enable Web3Forms' own spam filtering and domain restriction in its dashboard.
- Without JavaScript the form posts directly to Web3Forms and redirects to `/thank-you.html` only after Web3Forms accepts it.
- Fields sent: `name, company, email, phone, website, product_type, packaging, volume, stage, timeline, message`, plus `form_source`, `page_url`, `page_title`, `submitted_at` and first-touch attribution (`landing_page, referrer, utm_*, gclid`).
- The access key in `assets/config.js` is public by design (Web3Forms client keys are). Never put CRM tokens or other secrets there.

## Analytics

Set `ga4MeasurementId` in `assets/config.js` to load GA4. If GTM/gtag is already on the page, the script reuses it; otherwise events go to `dataLayer`.

| Event | When |
|---|---|
| `generate_lead` | Only after the provider confirms receipt (params: `form_source, product_type, packaging, volume, stage, timeline`) |
| `form_start` | First interaction with the form |
| `form_step_complete` | Step 1 (project details) completed |
| `form_submit_error` | Submission not confirmed (`reason`: rejected / network / timeout / offline / config / spam) |
| `cta_click` | Any element with `data-cta` (`cta_id`) |
| `menu_open` | Mobile menu opened |

Mark `generate_lead` as a key event in GA4.

## SEO

- One H1 per page, unique titles/descriptions, canonical URLs on `https://beveragecopackingtx.com`, Open Graph/Twitter cards.
- JSON-LD: `Organization`, `WebSite`, `Service`, `BreadcrumbList`, `FAQPage` (visible FAQs only), `Article` for guides, `CollectionPage` for `/resources/`.
- `sitemap.xml` is generated; `robots.txt` excludes `/thank-you.html`. Submit the sitemap in Google Search Console.
- Keyword → page map and content plan: `marketing/seo-roadmap.md`.

## Compliance note

Copy stays general on regulation: no legality, licensing, MOQ, capacity, shelf-life or turnaround promises, and the site states it is an introduction service, not a facility. Have counsel review before launch and before adding partner-specific capability claims. See `marketing/brand-guide.md`.
